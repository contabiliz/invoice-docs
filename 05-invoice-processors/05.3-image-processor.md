# 05.3 Image Processor

## 05.3.1 Overview

The image processor handles thermal receipt images and scanned PDFs rerouted from the PDF branch. Unlike XML (fixed schema) and PDF (spatial geometry), image documents have no machine-readable structure — they are raw raster images of printed receipts. The processor applies Pillow preprocessing to normalize the image, then calls the Gemini API in structured output mode to extract fiscal fields.

This branch is the most expensive, the slowest, and the only one with an external dependency at extraction time (`GEMINI_API_KEY`). It is used only when text-based extraction is not possible.

---

## 05.3.2 Architecture Decision Records

### ADR-001 — Use google-genai SDK, Not google-generativeai (H-18)

**Decision:** Use the `google-genai` Python SDK (`from google import genai`). Do not use `google-generativeai`.

**Reasons:**
- `google-generativeai` is deprecated. Google has announced it will not receive new features and may be removed.
- `google-genai` is the current SDK and receives all new Gemini capabilities including the structured output mode required by this processor.
- Mixing the two SDKs in the same environment causes version conflicts.

**Consequences:** All Gemini calls use `genai.Client`, `types.GenerateContentConfig`, and `types.Schema`. No imports from `google.generativeai`.

---

### ADR-002 — Structured Output Mode, No Prompt Interpolation (H-10)

**Decision:** Use Gemini's structured output mode (`response_mime_type="application/json"` with `response_schema`). Never interpolate document content into the instruction prompt.

**Reasons (finding H-10 — Prompt Injection):**
- A thermal receipt image contains printed text. If the system described the image content in words and passed it to Gemini as part of the instruction, malicious text printed on a receipt could override extraction instructions.
- Structured output mode passes the document as image bytes and requests a JSON response conforming to a schema. The instruction text describes only the schema structure — not the document content. There is no interpolation vector.
- Structured output also guarantees the response conforms to the schema, eliminating shape-mismatch errors.

**Consequences:** The instruction prompt is static — it does not change per document. Prompt updates are deploys, not runtime decisions. The response schema must be defined as a `types.Schema` (not a raw string) to enable strict validation on Gemini's side.

---

### ADR-003 — Extractor Interface for Dependency Injection

**Decision:** Define a `GeminiExtractor` protocol (or ABC) that the image processor depends on. The production implementation calls the real Gemini API. Tests inject a `FakeExtractor`.

**Reasons:**
- Gemini calls are expensive (cost) and slow (latency). Tests that call the real API are not unit tests — they are integration tests that require credentials, incur cost, and are flaky.
- The extractor interface decouples the preprocessing pipeline (Pillow, resize, contrast) from the API call. Preprocessing can be unit-tested independently.
- `invoice-processors` must not require `GEMINI_API_KEY` to be set during test runs.

**Consequences:** `ImageProcessor.__init__` receives an `extractor: GeminiExtractor` argument. The `invoice-pipeline` worker constructs the real extractor (with the API key) and injects it. Tests inject a fake.

```python
class GeminiExtractor(Protocol):
    def extract(self, image_bytes: bytes) -> dict: ...
```

---

### ADR-004 — Pydantic Validation Before Any DB Write (H-11)

**Decision:** The raw Gemini response dict must be validated through a Pydantic model (`ImageExtractionResult`) before the result is passed back to `invoice-pipeline`. If validation fails, raise a retryable exception.

**Reasons (finding H-11):**
- Gemini is an external service. Its response shape can change, fields can be absent, numeric fields can be returned as strings, dates can use unexpected formats. Writing unvalidated data to the database corrupts the `extracted_data` column.
- Pydantic validation produces a typed, normalized result — the same guarantee as XML XPath extraction.
- A validation failure is likely retryable: it may be a transient Gemini issue or a prompt/schema configuration problem that was just fixed and deployed. It should not silently store garbage.

**Consequences:** The Pydantic model for the Gemini response must mirror the `response_schema` exactly. If the schema changes, both must change together.

---

### ADR-005 — Pillow MAX_IMAGE_PIXELS Limit

**Decision:** Set `Pillow.Image.MAX_IMAGE_PIXELS` to 25,000,000 (25 MP) before opening any image. Do not disable the limit entirely (`MAX_IMAGE_PIXELS = None`).

**Reasons:**
- Pillow's default `MAX_IMAGE_PIXELS = 178,956,970` (~179 MP) is designed to prevent decompression bombs — maliciously crafted images that expand to enormous sizes and cause OOM.
- Thermal receipt images and scanned fiscal documents do not require more than 25 MP to be legible for OCR. A typical receipt at 300 DPI is under 5 MP.
- Disabling the limit entirely (`None`) removes protection against decompression bomb attacks. An attacker could upload a PNG that decompresses to several GB.

**Consequences:** Images larger than 25 MP are rejected as terminal failures. This threshold should cover all legitimate fiscal document types. If edge cases are discovered (e.g., very large format thermal printers), the limit can be raised with documented justification.

## 05.3.3 Processing Pipeline

```
bytes
  │
  ▼
Magic byte check (PNG: \x89PNG, JPEG: \xff\xd8\xff, TIFF: II/MM)
  │ mismatch → terminal failure
  ▼
Pillow.Image.open(BytesIO(bytes))
  │
  ▼
Decompression bomb check (MAX_IMAGE_PIXELS = 25_000_000)
  │ exceeds limit → terminal failure
  ▼
Contrast enhancement (thermal paper profile)
  │  ImageEnhance.Contrast(img).enhance(factor=2.0)
  │  ImageEnhance.Sharpness(img).enhance(factor=1.5)
  │
  ▼
Resize to target
  │  if pixel_count > TARGET_PIXELS: downscale maintaining aspect ratio
  │  encode as JPEG quality=85
  │  if JPEG bytes > MAX_BYTES: reduce quality iteratively (min quality=60)
  │
  ▼
extractor.extract(preprocessed_bytes)
  │  Gemini API call (structured output mode)
  │
  ▼
Pydantic validation: ImageExtractionResult.model_validate(response)
  │ validation error → raise retryable exception
  ▼
ExtractionResult (success)
```

## 05.3.4 Preprocessing

### Contrast Enhancement (Thermal Paper Profile)

Thermal paper images frequently suffer from:
- Low contrast between ink and paper (faded thermal printing)
- Uneven background (yellowed or wrinkled paper)
- Noise from scanning at angles

Enhancement parameters (thermal paper profile):

```python
CONTRAST_FACTOR = 2.0    # Strong contrast boost for faded thermal ink
SHARPNESS_FACTOR = 1.5   # Moderate sharpness to improve OCR signal
```

The enhancement is applied before resize. Resizing a low-contrast image degrades the already-poor signal.

### Resize Strategy

Target parameters:

| Parameter | Value | Rationale |
|---|---|---|
| `TARGET_PIXELS` | 2,000,000 (2 MP) | Sufficient for Gemini vision; balances latency and quality |
| `MAX_BYTES` | 4,194,304 (4 MB) | Gemini API inline image limit |
| `INITIAL_QUALITY` | 85 | Good quality JPEG with reasonable file size |
| `MIN_QUALITY` | 60 | Lower bound before re-evaluation |
| `FORMAT` | JPEG | Best size/quality ratio for photographs and printed documents |

Resize logic:

1. If `width * height > TARGET_PIXELS`: compute scale factor = `sqrt(TARGET_PIXELS / (w * h))`, resize with `LANCZOS` resampling.
2. Encode as JPEG at `INITIAL_QUALITY` into `BytesIO`.
3. If `bytes > MAX_BYTES`: reduce quality in steps of 5, re-encode until under limit or at `MIN_QUALITY`.
4. If still over limit at `MIN_QUALITY`: raise retryable exception (image cannot be reduced to API limit — log and retry, as this indicates an unusual image).

Images already under `TARGET_PIXELS` are encoded to JPEG at `INITIAL_QUALITY` without resizing. PNG and TIFF inputs are always converted to JPEG for the API call — do not send PNG to Gemini for fiscal documents (larger payload, no quality benefit for text extraction).

## 05.3.5 Gemini API Call

### Configuration

```python
from google import genai
from google.genai import types

client = genai.Client(api_key=GEMINI_API_KEY)

RESPONSE_SCHEMA = types.Schema(
    type=types.Type.OBJECT,
    properties={
        "cnpj_emitente":         types.Schema(type=types.Type.STRING),
        "nome_emitente":         types.Schema(type=types.Type.STRING),
        "documento_destinatario": types.Schema(type=types.Type.STRING),
        "nome_destinatario":     types.Schema(type=types.Type.STRING),
        "data_emissao":          types.Schema(type=types.Type.STRING),
        "valor_total_nota":      types.Schema(type=types.Type.STRING),
        "numero_nota":           types.Schema(type=types.Type.STRING),
        "items":                 types.Schema(
            type=types.Type.ARRAY,
            items=types.Schema(
                type=types.Type.OBJECT,
                properties={
                    "descricao":       types.Schema(type=types.Type.STRING),
                    "quantidade":      types.Schema(type=types.Type.STRING),
                    "valor_unitario":  types.Schema(type=types.Type.STRING),
                    "valor_total":     types.Schema(type=types.Type.STRING),
                }
            )
        ),
    },
)

INSTRUCTION = (
    "Extract fiscal information from this Brazilian fiscal receipt image. "
    "Return all monetary values as strings in the format found in the document. "
    "Return dates in the format found in the document. "
    "Return CNPJ/CPF without formatting. "
    "If a field is not found, return an empty string."
)

CONFIG = types.GenerateContentConfig(
    response_mime_type="application/json",
    response_schema=RESPONSE_SCHEMA,
    system_instruction=INSTRUCTION,
)
```

### Call Pattern

```python
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents=[
        types.Part.from_bytes(data=image_bytes, mime_type="image/jpeg"),
    ],
    config=CONFIG,
)
raw_dict = json.loads(response.text)
```

### Model Selection

Use `gemini-2.0-flash` (or the current production-recommended model from the Gemini API docs). Do not hardcode a specific model version that may be deprecated. Pin the model name in a configuration constant so it can be changed without a code change.

## 05.3.6 Response Validation

The Gemini response is validated before the result is returned to `invoice-pipeline`:

```python
from invoice_models.extraction import ImageExtractionResult

result = ImageExtractionResult.model_validate(raw_dict)
```

`ImageExtractionResult` mirrors the `RESPONSE_SCHEMA`. Fields declared as `STRING` in the schema are validated and normalized by Pydantic validators:

- `cnpj_emitente`: strip formatting, validate 14-digit check digit
- `valor_total_nota`: parse Brazilian decimal format → `Decimal`
- `data_emissao`: parse date string → `date` (multiple format fallbacks)
- `items`: validate each item's monetary and quantity fields

If `model_validate()` raises `ValidationError`, the exception propagates to `invoice-pipeline` as a retryable error. The document is not marked failed — it enters the retry cycle. If retries are exhausted, it goes to the DLQ for manual review.

## 05.3.7 What Not To Do

**Do not use `google-generativeai`.**
It is deprecated. Use `google-genai` (`from google import genai`).

**Do not interpolate document content into the instruction prompt.**
The instruction is static. Document content is passed as image bytes. Prompt injection via printed text on a receipt must not be possible.

**Do not disable `MAX_IMAGE_PIXELS`.**
Setting `Pillow.Image.MAX_IMAGE_PIXELS = None` removes protection against decompression bomb attacks. Use the defined limit (25 MP).

**Do not write to the database before Pydantic validation.**
An unvalidated Gemini response may have missing fields, wrong types, or malformed values. Always validate first.

**Do not call Gemini synchronously without the rate limiter.**
The image worker must acquire a token from the shared Redis token bucket before each Gemini call. See `04-invoice-pipeline/04.1-specification.md` §04.1.9 for the rate limiter implementation. Bypassing it destroys throughput by filling the DLQ with 429 errors under load.

**Do not send PNG to the Gemini API for fiscal documents.**
Convert all inputs to JPEG before the API call. PNG produces larger payloads with no OCR quality benefit for printed documents.

**Do not hardcode `GEMINI_API_KEY` in the processor.**
The processor receives an injected `GeminiExtractor`. The API key is injected at the worker level via environment variable. `invoice-processors` does not read environment variables directly.

**Do not treat Gemini 400/401 responses as retryable.**
A 400 is a malformed request (bad image, bad schema). A 401 is an invalid API key. Neither will succeed on retry. These are terminal failures. Only 429 and 5xx are retryable.

**Do not bypass the extractor interface in tests.**
Use `FakeExtractor` for unit tests. Never configure a real `GEMINI_API_KEY` in the unit test environment. Integration tests (with a real API key) belong in a separate test suite run in CI with explicit opt-in.
