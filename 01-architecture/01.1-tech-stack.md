# 01.1 Tech Stack

## 01.1.1 Frontend
  - Next.js: React framework for building full-stack web applications. You use React Components to build user interfaces, and Next.js for additional features and optimizations.

## 01.1.2 API
  - FastAPI: Python web framework for building the API layer. Handles batch submission, presigned URL generation, document metadata creation, and batch status queries. Chosen over Node.js alternatives to share the Python stack with the worker fleet, enabling shared Pydantic models between the API and Celery tasks.

## 01.1.3 Processing
  - **Consumer:** Python service that listens to Redis for S3 object-creation events. Reads the document's declared type from the database (no file download), updates the document status from `pending_upload` to `queued`, and publishes the Celery task to the appropriate processing queue.
  - **Workers:** Celery with Python. Celery is a simple, flexible, and reliable distributed system to process vast amounts of messages, while providing operations with the tools required to maintain such a system. The worker fleet contains three branches — image, XML, and PDF — each running on a separate queue with its own pool configuration.

## 01.1.4 Database
  - Supabase PostgreSQL: System of record. Stores batch metadata, per-document processing status, extracted fiscal data, and error reasons for failed documents.

## 01.1.5 Cache
  - Redis: Message broker between the Consumer and the Celery worker fleet. Holds the per-branch task queues and the Dead Letter Queue for tasks that have exhausted retries.

## 01.1.6 Storage
  - Supabase Storage: S3-compatible object storage for all uploaded raw files. The frontend uploads directly via presigned URLs generated by the API. Workers download files from here at processing time.
